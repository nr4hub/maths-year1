1

Overview

Probability is the maths of uncertainty: how likely is something to happen? It is a number from 0 (impossible) to 1 (certain), often written as a fraction, decimal or percentage.

Why developers need it
  • Spam filters & AI are built on Bayes’ theorem.
  • Hashing: how likely are two items to collide?
  • Reliability: chance that a request or disk fails.
  • Testing & A/B experiments: is a result luck or real?
How to use this page
  • Each idea starts in plain English with a small example.
  • Use the interactive tools to check your hand calculations.
  • Do the quiz, then the sample test on paper before opening the answers.
No maths background needed. If you can work with fractions (like 3/6 = 1/2), you can do everything here.
🐍 Why this matters for Python

Python can simulate chance with the random module. Running a simulation many times is a quick way to check a probability you calculated by hand.

💻 Software engineering
  • Testing code that uses randomness, and interpreting A/B experiments
  • Estimating reliability by simulation
🛡️ Cybersecurity
  • Risk and detection both start from 'how likely is this?'
  • Use the secrets module, not random, whenever unpredictability matters
🐍 Python example
import random
flips = [random.random() < 0.5 for _ in range(10000)]
print(sum(flips) / len(flips))   # about 0.5
සිංහල විස්තරය

සම්භාවිතාව (Probability) යනු: යමක් සිදුවීමේ ඉඩකඩ මැනීමයි. එය 0 (කිසිදා නොවේ) සිට 1 (අනිවාර්යයෙන්ම) දක්වා සංඛ්‍යාවකි; භාගයක්, දශමයක් හෝ ප්‍රතිශතයක් ලෙස ලිවිය හැක.

Python සමඟ: Python හි random module මගින් අහඹු සිදුවීම් අනුකරණය (simulation) කළ හැක. ඉහත කේතයෙන් කාසියක් 10,000 වතාවක් උඩ දමා head ලැබෙන අනුපාතය ආසන්නව 0.5 බව පෙන්වයි. ඔබ අතින් ගණනය කළ සම්භාවිතාවක් පරීක්ෂා කිරීමට simulation එකක් වේගවත් ක්‍රමයකි.

Software Engineering: spam filter, A/B testing, පද්ධති විශ්වසනීයත්වය (reliability), randomised කේත පරීක්ෂා කිරීම. Basics: outcomes & events

The three words to know
  • Outcome: one possible result (rolling a 4).
  • Sample space (S): the list of all possible outcomes. One die: S = {1, 2, 3, 4, 5, 6}.
  • Event: a group of outcomes you care about (“an even number” = {2, 4, 6}).
The main formula (equally likely outcomes): P(event) = number of outcomes in the event ÷ total number of outcomes.
Worked examples (one fair die)
  • P(rolling a 5) = 1 ÷ 6
  • P(an even number) = 3 ÷ 6 = 1/2
  • P(more than 4) = {5, 6} = 2 ÷ 6 = 1/3
The complement: “it does NOT happen”

Something either happens or it doesn’t, so the two chances add to 1: P(not A) = 1 − P(A). Example: P(not rolling a 6) = 1 − 1/6 = 5/6. This is a big shortcut for “at least one” questions.

Experiment: does the theory match reality?

Roll a virtual die many times. With few rolls the results are bumpy; with many, each face gets close to the theoretical 16.67% (1/6). This is the law of large numbers.

Press a button to roll.
🐍 Why this matters for Python

Python sets model a sample space and events directly: probability is len(event) / len(S).

💻 Software engineering
  • Monte Carlo simulation (repeating random trials) is built on the law of large numbers
  • Estimating how often a bug or failure shows up in tests
🛡️ Cybersecurity
  • Guessing a 4-digit PIN has probability 1/10,000 per try
  • The sample space of passwords decides how hard guessing is
🐍 Python example
S = {1, 2, 3, 4, 5, 6}
even = {x for x in S if x % 2 == 0}
print(len(even) / len(S))                  # 0.5
print(round(1 - len({6}) / len(S), 4))     # 0.8333  (not a 6)
සිංහල විස්තරය

මූලික වචන තුන: ප්‍රතිඵලය (outcome) — එක් විය හැකි ප්‍රතිඵලයක්; නියැදි අවකාශය (sample space, S) — විය හැකි සියලු ප්‍රතිඵල ලැයිස්තුව (දාදු කැටයකට {1,2,3,4,5,6}); සිද්ධිය (event) — ඔබට උනන්දුවක් ඇති ප්‍රතිඵල සමූහය (ඉරට්ටේ අංකයක් = {2,4,6}).

ප්‍රධාන සූත්‍රය: සමානව විය හැකි ප්‍රතිඵල සඳහා P(සිද්ධිය) = සිද්ධියේ ප්‍රතිඵල ගණන ÷ මුළු ප්‍රතිඵල ගණන. උදා: ඉරට්ටේ අංකයක් = 3/6 = 1/2. අනුපූරකය: P(A නොවේ) = 1 − P(A); උදා: 6 නොලැබීම = 1 − 1/6 = 5/6. 'අවම වශයෙන් එකක්' ප්‍රශ්නවලදී මෙය විශාල කෙටි මගකි.

Python සහ ක්ෂේත්‍රය: Python වල set භාවිතයෙන් S සහ සිද්ධි නිරූපණය කර len(සිද්ධිය)/len(S) ලෙස සම්භාවිතාව ගණනය කළ හැක. දාදු කැටය විශාල වාර ගණනක් පෙරළූ විට සෑම මුහුණතක්ම 1/6 ට ළඟා වේ — මෙය විශාල සංඛ්‍යා නියමය (law of large numbers) වන අතර Monte Carlo simulation වල පදනමයි. Cybersecurity වලදී ඉලක්කම් 4ක PIN එකක් අනුමාන කිරීමේ ඉඩකඩ එක උත්සාහයකට 1/10,000 ලෙස මෙසේ ගණනය වේ.

3

Counting: permutations & combinations

Many probability questions need you to count the number of ways something can happen. There are three tools.

1. The multiplication principle
  • If one choice can be made in a ways and another in b ways, together there are a × b ways.
  • Example: a 3-digit PIN (digits 0–9, repeats allowed) has 10 × 10 × 10 = 1000 possibilities.
2. Permutations: order MATTERS

nPr = n! ÷ (n − r)!

  • n! (“n factorial”) = n × (n−1) × … × 1. For example 5! = 5×4×3×2×1 = 120. By definition 0! = 1.
  • Example: gold, silver and bronze for 5 runners: 5P3 = 5!/2! = 120/2 = 60.
3. Combinations: order does NOT matter

nCr = n! ÷ ( r! × (n − r)! )

  • Example: choose a team of 3 from 5 people: 5C3 = 120 ÷ (6 × 2) = 10.
  • Each group of r people can be ordered r! ways, so nCr = nPr ÷ r!.
Quick test: if swapping the order gives a different result (podium places, passwords), use permutations. If not (a committee, a hand of cards), use combinations.
Calculator
🐍 Why this matters for Python

Python has counting built in: math.factorial, math.perm and math.comb. Counting tells you how big a search space is before you try to search it.

💻 Software engineering
  • An algorithm that tries all n! orderings becomes unusable very quickly
  • Counting configuration combinations tells you how many test cases you really have
🛡️ Cybersecurity
  • 95 printable characters, 8 long: 95^8 is about 6.6 quadrillion passwords
  • A 128-bit key has 2^128 possibilities, which makes brute force impractical
🐍 Python example
import math
print(math.factorial(5))   # 120
print(math.perm(5, 3))     # 60   (order matters)
print(math.comb(5, 3))     # 10   (order does not matter)
print(95 ** 8)             # 6634204312890625
සිංහල විස්තරය

ගණන් කිරීමේ මූලධර්ම: (1) ගුණ කිරීමේ මූලධර්මය: එක් තේරීමක් a ආකාරයෙන්ද තවත් එකක් b ආකාරයෙන්ද කළ හැකි නම් සමස්තය a × b. උදා: ඉලක්කම් 3ක PIN = 10×10×10 = 1000. (2) ප්‍රකාරණ (permutations, nPr = n! ÷ (n−r)!) — අනුපිළිවෙල වැදගත් විට (පොඩියම් ස්ථාන, මුරපද). (3) සංයෝජන (combinations, nCr = n! ÷ (r!(n−r)!)) — අනුපිළිවෙල අදාළ නොවන විට (කමිටුවක්, කාඩ් අතක්).

ෆැක්ටෝරියල්: n! = n × (n−1) × … × 1; 5! = 120; 0! = 1. උදා: ධාවකයන් 5දෙනෙකුගෙන් රන්, රිදී, ලෝකඩ: 5P3 = 60. පුද්ගලයන් 5දෙනෙකුගෙන් 3දෙනෙකුගේ කණ්ඩායමක්: 5C3 = 10. ඉක්මන් පරීක්ෂාව: අනුපිළිවෙල මාරු කළ විට ප්‍රතිඵලය වෙනස් නම් permutation; නොවෙනස් නම් combination.

Python සහ ක්ෂේත්‍රය: Python හි math.factorial, math.perm, math.comb මගින් මේවා ගණනය කරයි. Software Engineering වලදී n! ක්‍රියා සංඛ්‍යාවක් ඇති brute-force algorithm එකක් කෙතරම් මන්දගාමීදැයි සහ settings සංයෝජන සඳහා test case ගණන ගණනය කළ හැක. Cybersecurity වලදී අක්ෂර 95ක් භාවිතා කර දිග 8ක මුරපද ගණන 95⁸ ≈ 6.6 × 10¹⁵ වන අතර 128-bit key එකක් සඳහා 2¹²⁸ ක් වන නිසා brute force කිරීමට කොපමණ කාලයක් ගතවේදැයි තක්සේරු කළ හැක.

4

Combining events

Addition rule: “A OR B”

P(A or B) = P(A) + P(B) − P(A and B)

  • We subtract the overlap because it was counted twice.
  • Mutually exclusive events cannot both happen (a die cannot show 2 and 5), so the overlap is 0: P(A or B) = P(A) + P(B).
  • Example: draw a card. P(heart or king) = 13/52 + 4/52 − 1/52 (the king of hearts) = 16/52 = 4/13.
Multiplication rule: “A AND B”

Independent: P(A and B) = P(A) × P(B)

  • Independent means one event does not change the chance of the other (two separate coin flips).
  • Example: P(two heads) = 1/2 × 1/2 = 1/4.
  • Not independent (drawing without putting back): P(two aces) = 4/52 × 3/51 = 12/2652 = 1/221. After the first ace, only 3 aces remain in 51 cards.
Two-dice explorer

Roll two dice: there are 6 × 6 = 36 equally likely outcomes. Pick an event and the matching cells light up. Probability = highlighted cells ÷ 36.

🐍 Why this matters for Python

Python's set union (|) and intersection (&) match the OR and AND rules, and and / or conditions in code follow the same logic.

💻 Software engineering
  • Modelling two servers failing independently to estimate overall reliability
  • Combining conditions correctly in filters and queries
🛡️ Cybersecurity
  • Defence in depth: independent layers multiply the chance an attack gets through
  • If each of 3 layers misses 10% of attacks, all three miss only 0.1% of them
🐍 Python example
cards = [(r, s) for r in range(1, 14) for s in "HDCS"]
hearts = {c for c in cards if c[1] == "H"}
kings  = {c for c in cards if c[0] == 13}
print(round(len(hearts | kings) / len(cards), 4))   # 0.3077  (16/52)
print(0.1 * 0.1 * 0.1)   # about 0.001 (three independent layers all miss)
සිංහල විස්තරය

එකතු කිරීමේ රීතිය (A හෝ B): P(A හෝ B) = P(A) + P(B) − P(A සහ B). අතිච්ඡාදනය දෙවරක් ගණන් ගත් නිසා අඩු කරයි. එකවර සිදු විය නොහැකි සිද්ධි (mutually exclusive) සඳහා අතිච්ඡාදනය 0 වේ. උදා: කාඩ්පතකින් හෘදය හෝ රජු: 13/52 + 4/52 − 1/52 = 16/52 = 4/13.

ගුණ කිරීමේ රීතිය (A සහ B): ස්වායත්ත (independent) සිද්ධි සඳහා P(A සහ B) = P(A) × P(B). උදා: කාසි දෙකම head = 1/2 × 1/2 = 1/4. ආදේශ නොකර ගැනීමේදී (without replacement) ස්වායත්ත නොවේ: aces දෙකක් = 4/52 × 3/51 = 1/221. දාදු කැට දෙකේ 36 ප්‍රතිඵල ඇති grid එකෙන් සිද්ධියක් තෝරා සම්භාවිතාව සොයන්න.

Python සහ ක්ෂේත්‍රය: Python වල set union (|) සහ intersection (&) මෙම රීති සමඟ ගැළපේ; and/or condition ද එසේමය. Software Engineering: servers දෙකක් ස්වායත්තව අසමත් වේ යැයි උපකල්පනය කර විශ්වසනීයත්වය ගණනය කිරීම. Cybersecurity: 'defence in depth' — ආරක්ෂණ ස්ථර 3ක් සෑම එකක්ම ප්‍රහාර 10%ක් මග හරින්නේ නම් (ස්වායත්තව) තුනම අසමත් වීමේ ඉඩකඩ 0.1 × 0.1 × 0.1 = 0.001.

5

Conditional probability & Bayes

Plain English: conditional probability asks “given that we already know B happened, how likely is A?” Knowing B shrinks the sample space to just B.
Conditional probability

P(A | B) = P(A and B) ÷ P(B)

  • Read “P(A | B)” as “probability of A given B”.
  • Example: roll a die. Given the number is even, what is P(more than 3)? Even = {2, 4, 6}; of those, {4, 6} are above 3. Answer = 2/3.
Worked example: a bag (tree thinking)

A bag has 3 red and 2 blue balls. Draw two without replacement.

  • P(both red) = 3/5 × 2/4 = 6/20 = 3/10
  • P(one of each) = (3/5 × 2/4) + (2/5 × 3/4) = 6/20 + 6/20 = 3/5
  • Multiply along a branch; add the branches that give the event.
Bayes’ theorem: flipping the condition

P(A | B) = P(B | A) × P(A) ÷ P(B)

  • where P(B) = P(B|A)·P(A) + P(B|not A)·P(not A).
  • Spam example: 20% of emails are spam. The word “free” is in 60% of spam and 5% of non-spam. An email contains “free”. P(spam | free) = (0.6 × 0.2) ÷ (0.6 × 0.2 + 0.05 × 0.8) = 0.12 ÷ 0.16 = 0.75.
Bayes calculator (with natural frequencies)
Beware: P(A | B) is not the same as P(B | A). A test can be 99% accurate yet still give mostly false alarms when the thing it looks for is rare. Try setting spam to 1% and the false-alarm rate to 5%.
🐍 Why this matters for Python

Bayes' theorem is a few lines of Python, and it is the core of Naive Bayes spam filters.

💻 Software engineering
  • Spam filters, recommendations and diagnostic tools all update beliefs with Bayes
  • P(A | B) and P(B | A) are different, so mixing them up is a real bug
🛡️ Cybersecurity
  • Intrusion alerts are mostly false alarms when real attacks are rare (base-rate fallacy)
  • Bayes' theorem tells you how much to trust an alert
🐍 Python example
p_spam, p_w_spam, p_w_ham = 0.2, 0.6, 0.05
p_word = p_w_spam * p_spam + p_w_ham * (1 - p_spam)
print(round(p_w_spam * p_spam / p_word, 2))   # 0.75
සිංහල විස්තරය

අවස්ථානුගත සම්භාවිතාව (conditional): B සිදු වී ඇති බව දැනගෙන සිටින විට A සිදුවීමේ ඉඩකඩ: P(A|B) = P(A සහ B) ÷ P(B). B දැන ගැනීමෙන් නියැදි අවකාශය B වලට පමණක් කුඩා වේ. උදා: දාදු කැටය ඉරට්ටේ නම් {2,4,6} අතරින් 3ට වඩා වැඩි {4,6} — පිළිතුර 2/3.

බේස් ප්‍රමේයය (Bayes' theorem): P(A|B) = P(B|A) × P(A) ÷ P(B), P(B) = P(B|A)P(A) + P(B|A නොවේ)P(A නොවේ). Spam උදාහරණය: ඊමේල් 20% spam; 'free' වචනය spam වලින් 60%ක සහ spam නොවන ඒවායින් 5%ක ඇත. ඊමේලයක 'free' ඇත්නම් spam වීමේ ඉඩකඩ = 0.12 ÷ 0.16 = 0.75.

Python සහ ක්ෂේත්‍රය: මෙම ගණනය Python කේත පේළි 3කින් ලිවිය හැක; spam filter වල Naive Bayes ක්‍රමයේ හදවත මෙයයි. P(A|B) සහ P(B|A) සමාන නොවේ. Cybersecurity වලදී intrusion detection alert බොහොමයක් false alarm වන්නේ ප්‍රහාර ඉතා විරල නිසාය (base-rate fallacy); බේස් ප්‍රමේයය මෙය නිවැරදිව තේරුම් ගැනීමට උපකාරී වේ.

6

Binomial & expected value

Expected value (the long-run average)

A random variable X is a number produced by chance (e.g. the value of a die roll). The expected value is the average you would get over many repeats:

E(X) = Σ x · P(x)   (multiply each value by its probability, then add)

Fair die
  • E(X) = 1·(1/6) + 2·(1/6) + … + 6·(1/6) = 21/6 = 3.5. (You never roll 3.5, but the long-run average is 3.5.)
  • Variance measures spread: Var(X) = E(X²) − [E(X)]². For a die: 91/6 − 3.5² = 35/12 ≈ 2.92. Standard deviation σ = √Var ≈ 1.71.
The binomial distribution

Use it when you repeat the same yes/no trial n times, each independent with the same success chance p, and count the successes X.

P(X = k) = nCk · pk · (1 − p)n − k

  • Mean = np. Variance = np(1 − p).
  • Example: flip a coin 3 times. P(exactly 2 heads) = 3C2 · (1/2)² · (1/2) = 3 × 1/8 = 3/8.

Bars at or below k are blue, so their total height is P(X ≤ k). Try n = 5, p = 0.1: a server where 10% of requests fail.

🐍 Why this matters for Python

math.comb gives you the binomial formula in two lines. Expected value is a sum of value × probability.

💻 Software engineering
  • If a request fails 10% of the time, the expected failures and the retry plan follow from the binomial
  • Expected value helps compare options under uncertainty
🛡️ Cybersecurity
  • Probability of k failed logins decides when an account lockout should trigger
  • Expected number of events helps size alert thresholds
🐍 Python example
import math

def binom(n, k, p):
    return math.comb(n, k) * p ** k * (1 - p) ** (n - k)

print(round(binom(5, 1, 0.1), 5))                    # 0.32805
print(round(sum(x / 6 for x in range(1, 7)), 2))     # 3.5
සිංහල විස්තරය

අපේක්ෂිත අගය (expected value): random variable X (සසම්භාවී විචල්‍යය) යනු අහඹු ලෙස ලැබෙන සංඛ්‍යාවකි. දිගු කාලීන සාමාන්‍යය E(X) = Σ x·P(x). සාධාරණ දාදු කැටය: (1+2+3+4+5+6) ÷ 6 = 3.5. විචලතාව Var(X) = E(X²) − [E(X)]² = 35/12 ≈ 2.92; සම්මත අපගමනය σ = √Var ≈ 1.71.

ද්විපද ව්‍යාප්තිය (binomial): එකම ඔව්/නැත පරීක්ෂණය n වතාවක්, ස්වායත්තව, සෑම වරකම සාර්ථක වීමේ ඉඩකඩ p ලෙස පවතින විට සාර්ථක වාර ගණන X. P(X=k) = nCk · pᵏ · (1−p)ⁿ⁻ᵏ; මධ්‍යනය np; විචලතාව np(1−p). උදා: කාසිය 3 වතාවක් — හරියටම head 2ක් = 3C2 × (1/2)³ = 3/8.

Python සහ ක්ෂේත්‍රය: math.comb භාවිතයෙන් binomial සූත්‍රය Python වල පේළි දෙකකින් ලිවිය හැක. Software Engineering: request එකක් අසමත් වීමේ ඉඩකඩ 10% නම් retry ගණන සහ අපේක්ෂිත අසමත් වීම් (np) ගණනය කිරීම. Cybersecurity: වැරදි login උත්සාහ k ගණනක් සිදුවීමේ ඉඩකඩ ගණනය කර account lockout ප්‍රතිපත්තිය නිර්මාණය කිරීම.

7

The normal distribution

The famous bell curve describes many measurements (heights, test marks, errors). It is set by two numbers: the mean μ (centre) and the standard deviation σ (spread).

z-score and the 68–95–99.7 rule

z = (x − μ) ÷ σ

  • z tells you how many standard deviations x is from the mean.
  • About 68% of values lie within 1σ of the mean, 95% within 2σ, 99.7% within 3σ.
Default values (μ = 100, σ = 15, 85 to 115) give about 68%: exactly one standard deviation either side of the mean.
🐍 Why this matters for Python

Python's statistics.NormalDist gives probabilities for the normal curve without writing any integrals.

💻 Software engineering
  • Response times and measurement noise are often roughly normal
  • SLAs and 95th-percentile targets use this curve
🛡️ Cybersecurity
  • Learn a baseline (mean and standard deviation) of normal traffic, then flag values beyond 3 standard deviations
  • A z-score is a simple, explainable anomaly detector
🐍 Python example
from statistics import NormalDist
d = NormalDist(mu=100, sigma=15)
print(round(d.cdf(115) - d.cdf(85), 4))   # 0.6827

mean, sd = 50, 5          # normal logins per minute
z = (80 - mean) / sd
print(z)                  # 6.0 -> far beyond 3 standard deviations: suspicious
සිංහල විස්තරය

ප්‍රමත ව්‍යාප්තිය (normal distribution): සීනු ආකාර වක්‍රයක් — උස, විභාග ලකුණු, දෝෂ වැනි මිනුම් බොහොමයක් මෙයට අනුගත වේ. මධ්‍යනය μ (මැද) සහ සම්මත අපගමනය σ (පැතිරීම) මගින් එය නිර්ණය වේ.

z-score සහ 68–95–99.7 රීතිය: z = (x − μ) ÷ σ — x යනු මධ්‍යනයෙන් සම්මත අපගමන කීයක් ඈතද යන්න දක්වයි. අගයන්ගෙන් ආසන්න 68%ක් μ ± 1σ තුළ, 95%ක් μ ± 2σ තුළ, 99.7%ක් μ ± 3σ තුළ පිහිටයි. tool එකේ μ = 100, σ = 15, 85 සිට 115 දක්වා දුන් විට ප්‍රතිඵලය ≈ 68.3%.

Python සහ ක්ෂේත්‍රය: Python හි statistics.NormalDist(mu, sigma).cdf(x) මගින් සම්භාවිතා ලබා ගත හැක. Software Engineering: response time වල 95th percentile (SLA). Cybersecurity: සාමාන්‍ය traffic එකේ μ සහ σ දැන සිටියහොත් z > 3 වන අගයන් අසාමාන්‍ය ලෙස සලකා alert පනවයි (anomaly detection). ඉහත උදාහරණයේ z = 6 වන නිසා එය ඉතා සැක සහිතය.

Developer corner: collisions

A collision is when two items land on the same slot: two users with the same random ID, two keys in one hash bucket, two people with the same birthday. Collisions happen far sooner than most people expect.

The birthday problem

P(at least one collision) = 1 − (N−0)/N × (N−1)/N × … × (N−n+1)/N

  • We find the chance that nobody collides, then use the complement (1 − that).
  • With N = 365 days, only 23 people give a better-than-50% chance of a shared birthday.
  • Rule of thumb: collisions become likely after about √N items, not N.
23
This is why a 16-bit hash is useless for identifying files, and why random IDs need to be long (e.g. 128-bit UUIDs): the number of IDs you can create before a collision is about √N.
🐍 Why this matters for Python

This one-loop function shows how likely it is that two items collide. It is the maths behind hash tables and random IDs.

💻 Software engineering
  • Hash tables, UUIDs and load balancers all have collision behaviour
  • Collisions arrive after roughly √N items, not N
🛡️ Cybersecurity
  • Birthday attack: finding a collision in an n-bit hash takes about 2^(n/2) tries
  • Short tokens and IDs can be guessed or collided; MD5 and SHA-1 are weak partly for this reason
🐍 Python example
def collision_prob(n, N):
    p_no = 1.0
    for i in range(n):
        p_no *= 1 - i / N
    return 1 - p_no

print(round(collision_prob(23, 365), 4))   # 0.5073

Sample test + answers

Total 30 marks. Attempt each question on paper first, then click to reveal the full worked answer (marks shown in brackets).

Q1. Two fair dice are rolled. Find (a) P(sum = 8), (b) P(doubles), (c) P(sum is at least 10). [5 marks]
Worked answer: There are 36 equally likely outcomes. (a) Sum 8: (2,6) (3,5) (4,4) (5,3) (6,2) = 5 outcomes, so P = 5/36 [2] (b) Doubles: (1,1) … (6,6) = 6 outcomes, so P = 6/36 = 1/6 [1] (c) Sum 10: 3 ways, sum 11: 2 ways, sum 12: 1 way = 6 outcomes, so P = 6/36 = 1/6 [2]
Q2. (a) How many 3-digit PIN codes are possible (digits 0–9, repeats allowed)? (b) In how many ways can gold, silver and bronze go to 8 runners? (c) In how many ways can a committee of 3 be chosen from 8 people? [5 marks]
Worked answer: (a) 10 × 10 × 10 = 1000 [1] (b) Order matters: 8P3 = 8!/5! = 8 × 7 × 6 = 336 [2] (c) Order does not matter: 8C3 = 336 ÷ 3! = 336 ÷ 6 = 56 [2]
Q3. Events A and B are independent with P(A) = 0.6 and P(B) = 0.5. Find (a) P(A and B), (b) P(A or B), (c) P(neither). [4 marks]
Worked answer: (a) Independent: 0.6 × 0.5 = 0.30 [1] (b) P(A or B) = 0.6 + 0.5 − 0.30 = 0.80 [2] (c) P(neither) = 1 − 0.80 = 0.20 [1]
Q4. A bag holds 4 red and 6 blue balls. Two are drawn without replacement. Find (a) P(both red) and (b) P(one of each colour). [5 marks]
Worked answer: (a) 4/10 × 3/9 = 12/90 = 2/15 [2] (b) Red then blue: 4/10 × 6/9 = 24/90. Blue then red: 6/10 × 4/9 = 24/90. [2] Total = 48/90 = 8/15 [1]
Q5. 30% of emails are spam. The word "free" appears in 70% of spam and 10% of non-spam. (a) Find P(an email contains "free"). (b) Find P(spam | contains "free"). (c) Interpret the answer to (b) in words. [6 marks]
Worked answer: (a) P(free) = 0.7 × 0.3 + 0.1 × 0.7 = 0.21 + 0.07 = 0.28 [2] (b) Bayes: P(spam | free) = 0.21 ÷ 0.28 = 0.75 [3] (c) 75% of emails that contain "free" are spam. [1]
Q6. Each request to a server fails independently with probability 0.1. Five requests are made. Find (a) P(no failures), (b) P(exactly one failure), (c) the expected number of failures. [5 marks]
Worked answer: Binomial with n = 5, p = 0.1. (a) P(X = 0) = 0.9⁵ = 0.59049 [2] (b) P(X = 1) = 5C1 × 0.1 × 0.9⁴ = 5 × 0.1 × 0.6561 = 0.32805 [2] (c) E(X) = np = 5 × 0.1 = 0.5 [1]

  • Any answer can become an automatic check with assert
🛡️ Cybersecurity
  • Analysts must justify each step of a calculation in their reports

Cheat sheet

IdeaFormula
ProbabilityP(A) = outcomes in A ÷ total outcomes (0 to 1)
ComplementP(not A) = 1 − P(A)
Factorialn! = n × (n−1) × … × 1, 0! = 1
PermutationsnPr = n! ÷ (n−r)! (order matters)
CombinationsnCr = n! ÷ (r!(n−r)!) (order doesn’t matter)
Addition ruleP(A or B) = P(A) + P(B) − P(A and B)
IndependentP(A and B) = P(A) × P(B)
ConditionalP(A|B) = P(A and B) ÷ P(B)
BayesP(A|B) = P(B|A)·P(A) ÷ P(B)
Expected valueE(X) = Σ x·P(x); Var = E(X²) − [E(X)]²
BinomialP(X=k) = nCk·pk(1−p)n−k; mean np; var np(1−p)
z-scorez = (x − μ) ÷ σ; 68–95–99.7 rule

A cheat sheet works like API documentation: you do not memorise every rule, you know where to look.

💻 Software engineering
  • Quick reference while writing probability code
  • Helps you choose between permutation, combination, binomial and normal
🛡️ Cybersecurity
  • Fast lookup when reading risk or detection code
  • Reminds you of the independence assumption behind multiplying probabilities
